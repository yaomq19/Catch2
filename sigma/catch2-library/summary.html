  • 概念 4 轴校准：映射本对（前置用 REQUIRE、依赖项用 CHECK），但怀疑"REQUIRE 让两行不独立"——把判定轴从"兄弟之间是否独立"纠正为"后面有没有东西依赖它"。反例：前置若用 CHECK 失败，下游断言在已坏状态上跑 → 崩溃 / 误导性连锁失败。
  • 概念 5 深度坐实（三个自驱追问）：① 单 section ≈ 无 section（结果等价、机制不等价——探测会多跑一次 setup、语义上毫无意义）；② section 之外的代码每次调用都跑，含探测那次（多数人以为"section 没进，后面也不跑"——错）；③ 路径依赖：依赖共享状态的 trailing 断言，同一行两次运行给出相反结果 → 坏味道，应搬进建立该状态的 section。

关键洞察

  • REQUIRE vs CHECK 的判定轴：不是"这些断言之间是否独立"，而是"这行后面有没有断言 / 代码依赖它通过"。有 → REQUIRE（保护下游不在坏状态上跑）；无 → CHECK（收集所有失败）。
  • SECTION 执行模型：每个叶子 section 从共享 setup 的新鲜副本出发，兄弟 section 互相独立、互不可见；路径数 = section 个数（外加一次探测调用）。
  • 路径依赖坏味道：依赖共享状态的断言必须住进建立该状态的 section，否则其真假随路径漂移、等于没在断言一件确定的事。
  • SECTION 使用前提：≥2 条路径共享同一段 setup 才值得用；单路径直接写平铺。
