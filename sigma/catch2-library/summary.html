  • 概念 8 · 练习（score_after）：输入覆盖系统（等价类 × 边界 × 触顶/超顶/INT_MAX），期望值全对，INT_MAX 顺手覆盖整数溢出。两处分析性要求（封顶连续性判断 / precondition 处理）首提交漏写，提示后两题都对——执行缺口，非概念缺口。

关键洞察

  • 边界值分析的真实条件：< 与 <= 只在边界那一个点上分歧。函数在该点跳变（两分支 disagree）→ 符号 bug 被抓；连续（两分支 agree，如 clamp / min 封顶）→ 符号 bug 隐身，任何输入都抓不到。
  • precondition ≠ 抛异常守卫：precondition = 调用者责任 + UB + 不测；guard = 函数自检 + 抛异常 + REQUIRE_THROWS_AS。签名写哪个词，决定测什么。
  • 列一堆输入 ≠ 有价值：有的 case 抓不到任何 bug（连续函数的边界）。测试设计的核心判断力是"哪些输入真正暴露 bug"。
  • 极值 / 溢出是合法测试目标：current + steps 在 naive 实现下可能整数溢出（UB），大 steps 输入能逼实现"先比较再相加"。
